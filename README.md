# BDD 工作台

工作台綁定多個 Spec Repo；產品隸屬各 Spec Repo 的 `projects/`。**SQLite 儲存設定、需求、設計、測試草稿、人工確認與產品編輯；Git 是綁定、同步及固定驗收版本的輸出，不是按下儲存的前置條件。**

## 開始使用

使用 Node.js 24。在本機啟動：

```sh
npm start
# http://127.0.0.1:4173/
```

先填規格庫網址與確認者，即可儲存設定、用白話建立需求。儲存不會 Clone、查詢遠端、要求乾淨 checkout 或建立 commit。離線、遠端憑證錯誤、工作目錄有草稿時，仍能儲存到 `WB_HOME/metadata.sqlite`。

需要執行測試時，由管理者在可信任且隔離的主機啟用：

```sh
WB_ENABLE_TRUSTED_EXECUTION=1 npm start
```

主機仍須提供 Git、遠端憑證與瀏覽器系統相依套件。這個旗標不是 OS sandbox。首次需要測試套件與瀏覽器時，在流程中一次授權安裝，完成後接續同一步。

## 需求頁：只用上下兩個編輯區

上方 **需求描述** 可直接打字或按「上傳文件」匯入；按 **產生 Gherkin 草稿** 才會更新下方。下方 **Gherkin** 一直展開，是正式規格的主要編輯區，沒有功能名稱、角色、條件或案例 ID 等額外必填欄位。名稱由 Gherkin 的 Feature 自動取得。

修改上方不會覆蓋下方。重新生成前會保留原本下方內容到 SQLite 生成歷史，可以還原。「儲存」以同一筆 SQLite 交易保存描述及手動編輯的完整 Gherkin；未完成或格式有錯的草稿也可先存，只有「確認需求並繼續」才阻擋不完整規格。

支援 UTF-8 TXT、Markdown、Gherkin 與 DOCX（1 MiB 內），提取文字放入上方；目前不支援 PDF、掃描圖片或舊 DOC。這版生成器是本機格式草稿整理，不呼叫 LLM，也不宣稱已理解或驗證業務邏輯。產生的格式由回歸測試以官方 Cucumber parser 檢查，實際測試接線及完整 discovery 仍在測試階段驗證。

## 日常操作

| 操作 | 實際效果 |
|---|---|
| **儲存設定／需求／產品** | SQLite 交易同時寫入內容、修訂、設定及儲存收據。與 Git、網路和遠端同步無關。 |
| **確認需求／設計並繼續** | 以目前內容摘要記錄人工確認到 SQLite，不需要 Repo checkout。 |
| **確認測試並繼續** | 輸出已儲存版本、檢查必要套件、執行真實 discovery；通過才確認測試。 |
| **開始驗收** | 將固定 SQLite 修訂輸出到受管理 Repo，再建立隔離候選、執行及封存證據。 |
| **遠端同步** | 將已儲存內容輸出，依序同步產品、Spec、報告。失敗只影響同步，不撤銷已儲存內容。 |

產品原始碼尚未下載時，開啟產品編輯會自動取得；這不是儲存設定的一部分。設定可先綁定來源，之後再連線。新綁定的既有 Spec Repo 在首次同步／準備時讀入原有規格，不以本機草稿覆蓋同名不同內容。

同一份內容被另一個編輯者改變時，會保留畫面草稿並提示合併；這是內容衝突，不是 Git 的 Commit／dirty 錯誤。已儲存與已同步分開顯示。同步或輸出遇到 Repo 內的外部修改時，不強制覆寫，仍可繼續在 SQLite 編輯與儲存。


回歸測試涵蓋 SQLite 交易回滾、版本衝突、重啟恢復、離線保存、同步失敗後保存、舊 dirty checkout 匯入與原稿保留。瀏覽器驗收透過 UI 完成設定、儲存、內容確認、一次安裝授權、真實失敗、產品修正、成功驗收及同步；也包含移除測試遠端後儲存並重新載入。

隔離 bare remotes 的推送測試不代表已驗證使用者的私有 GitHub 憑證。Gherkin 表單產生草稿，不會假裝已實作、已確認或已通過測試。
